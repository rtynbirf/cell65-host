# PAC «Антицензор» — маршрутизатор блокировок в одном файле

PAC-скрипт (Proxy Auto-Configuration) — маленькая программа, которую браузер или
Windows спрашивает при каждом заходе: «этот сайт — через прокси или напрямую?».
Файл `anticensor.pac` содержит фильтр Блума на **129 103 заблокированных домена**
(экспорт реестра РФ от проекта «АнтиЗапрет», дата сборки — в шапке файла):
заблокированные домены идут через прокси, всё остальное — напрямую, без потери
скорости. Файл весит 456 КБ — влезает в лимит Windows для PAC-скриптов.

**Честно сразу:** PAC сам ничего не шифрует и не прячет — он только раскладывает
маршруты. Шифрование даёт прокси, к которому файл отправляет заблокированные
домены. Поддомены заблокированных доменов тоже идут через прокси. Пропусков в
фильтре нет (проверено сборщиком); ложные срабатывания ~0.1% — незаблокированный
сайт изредка пойдёт через прокси, это безвредно.

## Два пути

| Путь | Что нужно | Кому подходит |
|---|---|---|
| **А. Через свой узел** | VPS с СУВЕРЕННЫМ УЗЛОМ + `enable-pac-endpoint.sh` + пересборка PAC со своим IP | суверенно: трафик заблокированных сайтов идёт через ТВОЙ сервер |
| **Б. Публичный PAC «АнтиЗапрет»** | ничего, только ссылка | быстро, за 2 минуты, но трафик идёт через чужой сервис |

## Путь А — через свой узел (4 шага)

1. **На VPS**: `sudo bash enable-pac-endpoint.sh` (лежит в `sovereign-node/server/`).
   Добавит к sing-box вход `mixed :3128` с логином/паролем (пароль сам сгенерирует
   и допишет в `server.env`), проверит конфиг и перезапустит службу. Рабочая
   конфигурация не трогается, пока новая не пройдёт `sing-box check`.
2. **Пересобери PAC со своим адресом** (на любой машине с Python 3):
   `python3 build-anticensor-pac.py --proxy ТВОЙ_VPS_IP:3128`
   — скачает свежий реестр, соберёт фильтр, проверит пропуски и напечатает статистику.
3. **Выложи** полученный `anticensor.pac` в репу: `sovereign-node/pac/anticensor.pac`.
   Без всякого Pages файл уже доступен по raw-адресу (именно его вставляй в настройки):
   `https://raw.githubusercontent.com/rtynbirf/cell65-host/main/sovereign-node/pac/anticensor.pac`
   Опционально включи GitHub Pages (Settings → Pages → main → Save) — тогда тот же
   файл откроется и по `https://rtynbirf.github.io/cell65-host/sovereign-node/pac/anticensor.pac`.
4. **Включи PAC на устройстве** (см. ниже) и проверь.

Ленивый вариант шага 2 без Python: открыть `anticensor.pac` в веб-редакторе GitHub
(карандаш), заменить в единственной строке `PAC_PROXY = 'PROXY 127.0.0.1:3128; DIRECT'`
адрес на `PROXY ТВОЙ_VPS_IP:3128; DIRECT`, закоммитить. Дефолтная строка намеренно
нейтральная: пока она не указывает на живой прокси, PAC просто неактивен и ничего не ломает.

## Путь Б — публичный PAC (без своего VPS)

Адрес: `https://p.thenewone.lol:8443/proxy.pac` — сервис «АнтиЗапрет», прокси уже
встроены в их скрипт, работает только с российских IP. Вставь этот адрес туда же,
куда вставляется наш файл (см. ниже). Минусы: заблокированные сайты идут через
чужой сервис, его доступность вне твоего контроля. Для суверенной коробки — путь А.

## Куда вставить адрес PAC

- **Windows 11/10 (системно, для всех браузеров разом):**
  Параметры → Сеть и интернет → Прокси → «Использовать сценарий настройки» → ВКЛ →
  «Адрес скрипта» → вставь URL PAC → Сохранить.
- **Firefox** (своя настройка, независимая от системы):
  `about:preferences#general` → внизу «Параметры сети» → «Настроить…» →
  «URL автоматической настройки прокси» → URL → ОК.
- **Chrome / Edge / Яндекс.Браузер**: системная настройка Windows (выше) — или
  расширение («Обход блокировок Рунета», SwitchyOmega): в расширение можно скормить
  и URL PAC, и свой прокси напрямую.
- **Android (Wi-Fi)**: долгий тап на сети → «Изменить» → «Прокси» →
  «Автонастройка прокси» → URL. Через мобильный интернет PAC не работает — там
  только VPN-приложения.
- **Устройства без администратора** (рабочий ноутбук): Firefox portable или
  расширение в браузере — системные настройки трогать не нужно.

Если на прокси включён пароль (путь А) — браузер сам спросит логин/пароль при
первом заходе на заблокированный сайт и запомнит его.

## Проверка

1. Открой `2ip.ru` или `ifconfig.me` — должен показываться **твой домашний IP**
   (PAC не гоняет всё через прокси, только заблокированное).
2. Открой заведомо заблокированный сайт — должен открыться.
3. `https://bash.ws/dnsleak` — для проксируемых сайтов резолвер будет «проксийный»,
   для остальных — твой провайдер. Так и задумано: домен сайта прокси получает
   только для заблокированных.
4. PAC «не работает»? Отключи адблокер-расширение и повтори — расширения,
   перехватывающие прокси, ломают загрузку скрипта (частая история из issues
   «Антицензорити»).

## Пересборка (свежий реестр)

```bash
python3 build-anticensor-pac.py --proxy ТВОЙ_VPS_IP:3128
```

Скачивает текущий экспорт реестра, пересобирает фильтр, проверяет выборку на
пропуски и меряет ложные срабатывания. Реестр живой — пересобирай раз в месяц.
Офлайн-вариант: скачай `domains-export.txt` вручную и вызови с `--list путь/к/файлу`.

## Границы (честно)

- PAC маршрутизирует, но не шифрует: `https` остаётся `https` от тебя до сайта.
- Покрываются **доменные** блокировки; IP-блокировки (блокировка подсетей) — нет.
- IE не поддерживается; Windows 10/11, Firefox, Chromium, Android (Wi-Fi) — да.
- Фильтр Блума внутри файла: ~0.1% ложных «проксируй это» на чистых сайтах,
  пропусков заблокированных нет.
- PAC-адрес по http (не https) на своей площадке GitHub Pages не встретится —
  Pages отдаёт https, это правильно.
